## Contract

CD audio start-up. Zeroes 0x524658/0x52465c, calls 0x423b30 (opens the MCI cdaudio device, sets TMSF, finds the
aux CD line; returns nonzero on failure -> this function returns 0). On success sets 0x524674 = 1 and sends
MCI_STATUS (0x814) with MCI_STATUS_ITEM (0x100), item 4 (MCI_STATUS_MODE). If that fails the device is closed
(MCI_CLOSE 0x804), 0x4ed890 = -1, 0x524674 = 0 and state 5 is stored in 0x524670. On success the returned mode
minus 0x20d (MCI_MODE_STOP) indexes jump table 0x423f54 (stop->2, play->3, record/seek->5, pause->4, open->1),
but in the reference image the bounds check at 0x423f0c is `mov eax,0; nop`, so the index is always 0 and the
state is always 2. The state switch (table 0x423f44): 1 closes the device and returns 0; 2/3 call 0x4249a0 with
0x524588 (reads the track count and per-track MCI_STATUS positions into that table); 4 does the same and then
MCI_STATUS item 2 (MCI_STATUS_POSITION) and splits the TMSF dword into 0x524660 (track), 0x524664 (minute),
0x524668 (second), 0x52466c (frame). Finally it takes the low byte of 0x654b90 (1 treated as 0), multiplies by
0xccc, clamps to 0xffff, and if 0x4ed894 != -1 calls auxSetVolume with that value in both halves; returns 1.

## Hypotheses

- hypothesis: 0x654b90 low byte looks like a music volume setting in 0..20 steps (0xccc * 20 = 0xfff0); only its use as the auxSetVolume level is seen here, so no global claim
- hypothesis: the 6 bytes b8 00 00 00 00 90 at 0x423f0c probably replaced a `ja` near jump (0f 87 rel32) in a patched release, forcing state 2 after any successful MCI_STATUS_MODE query
- hypothesis: 0x524658 and 0x52465c are zeroed on entry; their meaning is not visible in this function
- hypothesis: 0x524588 is the CD track table filled by 0x4249a0 (first track, count, per-track positions)
