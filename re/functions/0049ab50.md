## Contract

Opens the file named by param_1 with MSVCRT _open(path, 0x8000 = _O_BINARY), reads the first dword into
param_2[0] and switches on it. If the dword is 0x324b4d53 (the bytes "SMK2", the Smacker file signature) it
reads the rest of a Smacker header into the caller's 36-dword record: width [1], height [2], frame count [3],
frame-rate word [6]; the frame-rate word is normalised to a per-frame duration in 10 us units (negative value
= already in that unit, positive = milliseconds * 100), from which it derives fps integer [4], fps tenths [5],
ms per frame [6] and tenths of ms [7]. The flags dword is split into [0xb] = bit0, [0xc] = bit1, [0xd] = bit2;
if bit1 or bit2 is set the height [2] is doubled. Then it reads 7 dwords of audio sizes into [0x16..0x1c], 5
dwords into [0x1d..0x21], 7 audio-rate dwords into [0xf..0x15] and one dword into [0x1d]. For each of the 7
audio tracks: size==0 -> rate=0; rate without bit 30 -> rate=-1; otherwise the size slot [i+7] becomes 16 or 8
depending on bit 29, [i+0xe] becomes bit 28, and rate is masked to 24 bits. It then streams the per-frame size
table (frames, +1 if [0xb] is set) 512 bytes at a time, accumulating the sum into [8] and the maximum into [9],
divides [8] by the frame count (average frame size), stores _lseek(fd,0,SEEK_END) (file size) into [0xe],
closes and returns 1. If the first dword is 0x614b4d53 or 0x624b4d53 it closes the file, zeroes all 36 dwords
of the record and writes 0x314b4d53 into [0], returning 1. Any other signature (or a failed _open) returns 0.

## Hypotheses

- hypothesis: The record is a 36-dword summary: [0] signature, [1] width, [2] height (doubled for interlace/double), [3] frames, [4] fps, [5] fps tenths, [6] ms per frame, [7] tenths of ms, [8] average frame bytes, [9] max frame bytes, [0xb] ring-frame flag (bit0), [0xc] Y-interlaced (bit1), [0xd] Y-doubled (bit2), [0xe] file size, [0xf..0x15] audio rate per track, [0x16..0x1c] audio bits per track (8/16), [0x1d..0x23] audio stereo flag per track.
- hypothesis: The frame-rate arithmetic matches the Smacker header rule (FrameRate > 0 is milliseconds, < 0 is negated 1/100000 s), so [4]/[5] are fps and [6]/[7] are frame period; no evidence beyond the C shape.
- hypothesis: 0x614b4d53 / 0x624b4d53 (bytes SMKa / SMKb) name an alternate marker whose record is blanked to signature 0x314b4d53 (SMK1); what those files are is not visible from this function.
- hypothesis: The caller 0x0049a070 maps [0xd] to 0x4000 and [0xc] to 0x2000 and ORs them into the _SmackOpen@12 flags, consistent with Smacker Y-double / Y-interlace open flags; the caller is unverified so this is tu-neighbourhood flavour only.
- hypothesis: Return value is a 0/1 success flag (three return sites 0, two return 1).
