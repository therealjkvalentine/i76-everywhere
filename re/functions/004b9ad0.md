## Contract

A 20-byte wrapper around MSVCRT _stricmp: it loads [esp+4] and [esp+8], pushes them in order, calls
[0x4bc210] (_stricmp), cleans 8 bytes and returns with eax left as _stricmp's result (plain `ret`). It has no
direct callers; its address is pushed as an immediate at three .text sites, all in supported zfs functions:
0x4b9a7f in zfs_Open (comparator of qsort [0x4bc1e8] over the 0x24-byte directory records), 0x4b9b66 in
zfs_GetRecordSize and 0x4b9bfc in zfs_ReadRecord (comparator of bsearch [0x4bc148] with a 16-byte name key).
So it is the case-insensitive name comparator for the ZFS directory table. Ghidra types the return as void;
the eax pass-through and the qsort/bsearch consumers make it int.

## Hypotheses

- hypothesis: both arguments point at 0x24-byte ZFS directory records whose first 16 bytes are the entry name (strncpy 0x10 key in 0x4b9b40/0x4b9bd0, element size 0x24 in qsort/bsearch); a record-typed prototype would need the struct in types/i76.h
- hypothesis: conv is __cdecl in practice (plain ret, qsort/bsearch comparators are cdecl), but there is no direct call site, so gate K leaves it auto
