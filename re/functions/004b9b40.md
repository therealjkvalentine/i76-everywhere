## Contract

Copies the requested record name into a 16-byte key (strncpy, 0x10), bsearches the archive's directory
(entry array at archive+0x28, entry count at archive+0x18, entry size 0x24, comparator 0x4b9ad0 = _stricmp)
and returns -1 when the name is absent. For a found entry it returns the record size: when the entry flags
at +0x20 test any of bits 1|2 (test cl,6) the size is flags >> 8 (the unpacked size), otherwise the stored
size at entry+0x18. This is the same key/bsearch/flag logic zfs_ReadRecord 0x4b9bd0 (supported, same TU)
uses to pick its buffer size (it passes entry+0x18 as the read size and flags>>8 as the decompress size).
The sole caller 0x4b3310 treats -1 as 'Could not find record "%s" in file "%s"' (string 0x500024 is
referenced by the caller, not by this function) and otherwise returns the value as a file size, its other
branch being fseek/ftell on a loose file.

## Hypotheses

- hypothesis: flags bits 1|2 (mask 6) mark an LZO-compressed record and flags>>8 is the unpacked size; supported by zfs_ReadRecord passing flags>>8 to zfs_Decompress, but not proven inside this function
- hypothesis: entry +0x00..0x0f is the 16-char record name (strncpy 0x10 into the key compared by _stricmp)
