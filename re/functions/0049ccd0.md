## Contract

Takes a mission code string. NULL sets the global dword 0x4fe520 to 1 and returns. Otherwise it parses the string with
sscanf "%1s%2d" into a letter and a number. Letter 'n' (0x4fe528) gives 1 and letter 't' (0x4fe524) gives 2. Any other
letter is looked up in a .data table of 12-byte records {char letter at 0x4fe430+12i, int number at 0x4fe434+12i,
int value at 0x4fe438+12i} for i in 0..20 (bytes read from the pristine file: P1-P4, P17, P19 give 2; B1, P5-P8, P18
give 3; P9-P12 give 4; P13-P16 give 5). A letter+number match stores the record's value, and no match stores 1. The
sibling 0x49ccc0 returns 0x4fe520. Its callers format "ZNPD%1d01.map" and "ZSWLS%1d01.tmt" with it, so the value looks
like a map/terrain set number 1..5 chosen from the mission code. The only caller, WinMain at 0x4034da, passes NULL just
before bwd2_LoadMissionFile. The name words come from reading the code and are not hard-anchored.

## Hypotheses

- hypothesis: 0x4fe520 (read back by 0x49ccc0) is the terrain/map set number 1..5; consumers of 0x49ccc0 sprintf it into ZNPD%1d01.map / ZSWLS%1d01.tmt (read outside the bounded pack, sibling getter's callers)
- hypothesis: mission letters: t = training (value 2), n = default (value 1), P = plot missions, B = one bonus mission; the letter meanings are guesses from the table contents
- hypothesis: the only static call passes NULL, so in this build the lookup path may be dead or reached only through a path Ghidra did not record
