# shell\ — the I76SHELL.DLL track

A parallel track to the main i76.exe map: every menu, the garage, save/load and the bookmark screens.
Target: the pristine GOG `i76shell.dll`, md5 **`deb41008321cf018ba33c27bfbbfa074`**, copied from
`..\sandbox-gog\main\app\` into `bin\` (git-ignored like every image). The exe loads it by the name `I76SHELL.DLL`
(exe file offset 0xc1230). `I76SHELL_1083.DLL` (`d523756c`, 1997) sits in the same folder and is never loaded.
The portable's `i76shell.dll.orig` (`8960fa16`) is a patched pack build, not the original (see
`..\..\i76-everywhere\tools\bisect\README.md`).

Single-writer rule: this track writes only under `shell\`. Its tables use the main map's column format, plus
`module` and `evidence` columns, so the main session can merge them through its gates. Nothing here writes to
`symbols\`, `evidence\`, `functions\`, `status\queue.json`, `ghidra\proj` or `types\`.

## Rebuild the Ghidra project and export

```
powershell -ExecutionPolicy Bypass -File ghidra\scripts\build.ps1 -Proj <shell>\ghidra\proj -Out <shell>\ghidra\export ^
   -Exe <shell>\bin\i76shell.dll -Name i76shell -Scripts <shell>\ghidra\scripts          (608 functions)
analyzeHeadless <proj> i76shell -process i76shell.dll -postScript CreateFuncsAtList.java work\new_func_starts.txt ...
analyzeHeadless <proj> i76shell -process i76shell.dll -postScript RemoveFuncsAtList.java work\junk_func_starts.txt work\new_func_starts.txt
analyzeHeadless <proj> i76shell -process i76shell.dll -postScript ExportBaseline.java <export> -postScript DumpAll.py <export>
                                                                                       (721 functions)
```

The scripts are copies of `..\ghidra\scripts\` plus the two list scripts. `new_func_starts.txt` holds function-pointer
immediates and .data/.rdata dwords that point into `.text` at no existing function (113 after filtering).
`junk_func_starts.txt` holds 16 linear-sweep artifacts (`loop` operands decoded from CRT data) that were created and then removed.

## Code Ghidra does not list (from naming batch E)

`.text` 0x1003d460–0x1003e270 is a 901-entry 16.16 sine table read by `Mcga_SinCos` 0x1003e274, not code. That is why
linear sweeps desync there. Real but unreferenced code with no Ghidra function: 0x100385d0, 0x10038980, 0x10038c90,
0x100390f0, 0x10039480, 0x10039900, 0x10039940, 0x10039b30 ("Vehicle pool full" allocator), 0x1003fcf0 (joystick
"no devices configured"), and ShellMain's EH stub 0x100402b3 (pushed at 0x1001e262). Add them to
`work
ew_func_starts.txt` on the next Ghidra round.
