## 3. Rumble

**How the game's rumble reaches the Deck (found, then built):** nothing wrote vibration on the Deck before today. The AHK pad
layer's mixer is gated off (`gShimOwnsRumble := true`, since 2026-07-19 for the Mac's shim), the Deck's launcher on the device
predates the 2026-10-16 `I76_AHK_RUMBLE` block, the proxy's pad menu only reads XInput, and GOG's `i7_sfrce.dll` speaks only
DirectInput force feedback. The carrier that knows about **events** (shots, hits, landings) is the **ffb-shim** (`ffb-shim/`, a
replacement `i7_sfrce.dll`): the game hands it its 364-byte force block every tick. It had only ever been built with mingw on the
Mac; this lane built it with MSVC (`ffb-shim/build-msvc.ps1`, static CRT) and added `I76_FFB_PADS=all` (every connected XInput
slot: the Deck's controls and a paired Xbox pad), `XInputSetState` ok / fail counters and the written slot mask in the telemetry
(`pads= xok= xfail=`), and `land` / `fire` lines in the event log (commits 0aca0f4, 6853d7b).

- **A bug of mine, found by the Deck:** the first MSVC build (87340c73) ended the game at load, 3 of 3 (`rc=9` right after Glide
  init); the unmodified source built the same way booted (n 1). Cause: the longer init line overflowed the init function's
  `char m[64]`, and MSVC's /GS cookie terminated the process. Fixed (160), build **d6e9add5**.
- **Installed on the owner's Deck** (07:30, `tools\deck-20261025\deck-ffbshim.sh apply`): `game/i7_sfrce.dll` = d6e9add5,
  `game/rumble-envelopes.ini` (123 envelopes, made on the Deck from its own sound files by `tools/gpw-envelopes.py`; same count as the
  Mac), `export I76_FFB_PADS=all` in `i76-env.sh`. Backup `game/_rollback-ffbshim-20261025/` (GOG's `i7_sfrce.dll` 687cc35b + the
  env file); rollback `bash ~/i76-deck-20261025/deck-ffbshim.sh rollback`. Trade-off: GOG's DLL drives a DirectInput FFB **wheel**;
  with the shim a docked FFB wheel gets no force feedback (copy the backup back for that).

**Measured (rum3 / rum4, T05, n 2; the car placed 6.5 m above the crest by `I76_START_POS=7972,108,44035,-90,2`, then fire 3 s

So **rumble commands are issued on shots, collisions and landings and accepted by XInput slot 0** (Wine's xinput, Proton
GE10-12). Slot 0 is Steam Input's virtual pad for the Deck's own controls (`Microsoft X-Box 360 pad 0`, `/dev/input/event18`); it
advertises force feedback (`B: FF=10000 0` = FF_RUMBLE), and the account's `SteamControllerRumble` is -1 (Steam's default, on) with
intensity 320. Whether Steam turns those writes into the Deck's haptics is what the owner's hands decide (below).

**Xbox controller: not measured.** Four Xbox Wireless Controllers are paired to the Deck, **none was connected** at any check
(07:05, 07:28: `bluetoothctl info ... Connected: no`). Turning one on lets it reconnect by itself; then the shim writes slot 0 and
slot 1 (`pads=3` in `ffb-drive.log`). Steam Input mapping needed: **none beyond what is there** - the Deck's controls use the
shortcut's gamepad layout (`controller_neptune_i76_pad.vdf`); an Xbox pad has no game-specific config on this Deck
(`configset_controller_xboxone/xbox360/xboxelite.vdf` and the per-device `configset_45e-*.vdf` have no "interstate 76" entry), so
Steam gives it its default gamepad pass-through, which presents an XInput pad and forwards rumble. Do not turn Steam Input off.

## 4. The Deck Kit: end users building the Deck version

**Audit of `deck/deck-install.sh` against the Windows / Mac kits' standards:**

| standard | deck-install.sh (2026-07) | the Deck Kit (today) |
|---|---|---|
| nothing of GOG's redistributed | yes (innoextract on the user's installer) | yes; the packager refuses any file byte-identical to one of 326 GOG files |
| pinned downloads | **no**: repo files from `main` (unpinned), dgVoodoo zip and innoextract not hash-checked, GE-Proton "latest" from the GitHub API | every download by sha256 (`deck/kit/pins.txt`): innoextract 1.9, dgVoodoo 2.78.2, IPXWrapper 0.7.2, GE-Proton 10-12 (only with `--ge-proton`); our files travel in the zip, md5-pinned by the packager |
| dgVoodoo for Proton | 2.78.2 from archive.org | **2.78.2** kept: Proton needs <= 2.80 (2.81+ crashes at the first present under Wine's DXGI, dxvk#5217, DXGI-DGVOODOO-RESEARCH.md); not on Dege's GitHub, so the archive.org zip, pinned (sha256 b75f2f2e...), byte-identical to the owner's Deck. 2.87.5 (the Windows kits') is NOT for the Deck; not re-measured under GE10-12 this time |
| the proxy | **none** | `STRLKUP.DLL` 5d6f9828 (= every machine), GOG's kept as `strlkup_orig.dll` |
| exe / shell patches | none | the Mac Kit's Gold patches (shell keys, text entry, Wine PIT skip, the arenas) **without its u32x step** (`deck/kit/tools/make-deck-patches.py`, below), applied by a stdlib `bspatch.py` (SteamOS has no bspatch) |

**Built:** `deck/kit/` (i76-deck-kit.sh `install | steam | verify`, pins.txt, README.md, the preset, tools/), `tools/package-deck-kit.ps1`
(zip; commits 8c48960 .. d1d30e8). Zip: lab `downloads\deck-kit\Interstate76-Deck-Kit-i76-everywhere-v0.1.0-d1d30e8.zip` (1.1 MB,
md5 30c7aea9). `deck/deck-install.sh` carries a SUPERSEDED header.

**Tested as a user would, on the Deck, in a fresh folder** (`~/i76-kit-test-20261025`, its own Proton prefix
`.compatdata`, GOG's real offline installer `setup_interstate76_2.1.0.17.exe` md5 45c9538f copied over; the live install and its
prefix untouched; started the way the Steam entry starts it: `i76-deck-launch.sh <GE-Proton10-12 proton> waitforexitandrun
game/i76.exe -glide` on gamescope's display). Install = 32 s (downloads cached after the first), `verify` 47 / 47. The test found
four defects, each fixed and re-run:

1. **"Please insert CD 'Interstate '76 CD 2'"** at boot (a modal box; read with the probe's `boxtext`): an innoextract folder has
   none of GOG's registry keys (the Mac Kit's same finding). The kit writes `i76-gog-keys.reg` (`Minimum`="0" for "Interstate '76
   Gold Edition", `EXE`="i76.exe", both registry views); the launcher imports it once per prefix (Steam makes the prefix at the first
   start): `registry: GOG keys imported (2 Minimum lines, 2 s)`, then `present` on the next start. (The first try passed a `Z:\`
   path that arrived as `Z:`, and judged `system.reg` before wineserver had written it; both fixed.)
2. **The Mac Kit's u32x step breaks the Deck's menu pointer:** with u32x the proxy logged `exe PeekMessageA NOT found`,
   `i76shell.dll PeekMessageA NOT found` and `cursor-map: u32x.dll present ... not applied`. The Deck set (no u32x, as the owner's
   Deck since 2026-07) gives `exe PeekMessageA chained`, `i76shell.dll PeekMessageA chained`, `cursor-map: ... 4/4 USER32.dll slots
   repointed` in both modules, `mp-menu: skip ... patched, read back OK`, `arena-fit ... read back OK`.
3. PowerShell's `Compress-Archive` zip unpacked with backslash names and directories without the x bit (`payload/` unreadable):
   the packager writes the zip itself now (forward slashes, Unix modes).
4. curl's progress meter cluttered the install output (now quiet).

**Final kit, measured (exe ae383a69, shell 3f2fff4f, proxy 5d6f9828, shim d6e9add5):** T05 boots kitA / kitB: median 60.0 / 60.0,
1 % low 59.3 / 58.8, `coop-ai: 27/27`, 0 CRASH, the shim on pad 0; the shell boot (kit9) with every hook above read back.
Not tested: the `steam` step for real (only `--dry-run` against the owner's `shortcuts.vdf`: it parses, round-trips, writes nothing,
and showed it would UPDATE the existing "Interstate 76" entry - hence the name option), driving the kit's menus by stick (needs
hands), an OLED Deck, Proton Experimental, a GOG Galaxy folder as the source.
