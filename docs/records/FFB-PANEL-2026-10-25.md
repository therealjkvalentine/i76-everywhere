# FFB / LFE web panel and windowed mode (2026-10-25)

Owner's ask: "debug info for working FFB tuning in the web page (not a terminal), and some way to run the game in a window if
we're expecting to keep both up at the same time, including the differing things we want to be noticeable; same for LFE (on
defects only, never boosted on voice or music), telemetry etc."

## 1. What there is now

| piece | where | how to use |
|---|---|---|
| the page | `tools/ffb/ffb-panel.py` + `ffb-panel.html` (stdlib Python, one HTML file, no CDN, no build) | **http://127.0.0.1:17691/** - `FFB-WEB-PANEL.bat`, or `PLAY.bat --panel` |
| the feed | `tools/ffb/ffb-interposer.ps1` | publishes state to udp 127.0.0.1:17682 (20 Hz) + a tune / defaults datagram once a second; takes gate / arm commands on 17683; `-PanelPort 0` = off |
| live tune | the interposer | re-reads `ffb-tune-owner.json` when its time stamp changes (checked every 0.5 s), applies changed values in place, logs each one to the event log and `ffb-interposer.log` |
| the shaker | `tools/ffb/ffb-lfe-live.ps1` | now loads + live-reloads the same owner tune and reports its output level to the panel |
| windowed | `PLAY-i76.ps1 -Windowed [auto|WxH]`, `PLAY.bat --windowed [WxH]` | `auto` = the screen's shape, 880 px narrower: **2560x1070 on 3440x1440**, top left |
| panel with the game | `PLAY-i76.ps1 -Panel`, `PLAY.bat --panel` | starts the page when the interposer runs (a wheel is attached) |

The interposer's console panel is unchanged and stays the fallback.

### What is live-editable from the page

- **solo / mute** per channel, "all on", **force on / off** (commands to the interposer; this session only, like `-Only` / `-Mute` / `[space]`)
- **sliders** (write `ffb-tune-owner.json`, only values that differ from the defaults, read back; persistent):
  master; the 14 channel gains (SatGain, CornerGain, OversteerGain, BrakeGain, TextureGain, ScrubGain, JudderGain, ImpactGain,
  WeaponGain, ShiftGain, EngineGain, IgnitionGain, HitGain, LandGain); PavementScale, OffroadScale, SurfaceFadeMs,
  UndersteerDrop, BumpGain, KerbGain, RocketScale, MortarScale, FlameGain, DropGain, CycleGain, HitSideSign, MinForce; the LFE
  amplitudes LfeEngineAmp, LfeRoadAmp, LfeImpactAmp, LfeWeaponAmp, LfeHeaveAmp, LfeScrubAmp, LfeExplodeAmp. Range 0..3 x default
  (Master 0..1.5, HitSideSign +/-1). "def" resets one; "reset all" empties the file. A slider shows **applied** only when the
  interposer's own report carries the new value.
- **checklist verdicts**: 24 "things we want noticeable" (pavement / off-road / road edge, under / oversteer, braking, gun,
  rocket, mortar, flamer, dropper, weapon cycle, hit left / right / front-back, collision, landing, engine, ignition, gear, four
  shaker sources), each with when it last fired and felt it / not felt / too strong / too weak + a comment, appended to
  `notes\ffb-notes-<start time>.csv` beside the tune file with the gains involved and the last event.

Read-only: telemetry (speed, steer / throttle, yaw against the steering law, slip U / O, grip, slide, g, surface + texture
factor, gear, rpm, jolt, ammo per weapon, engine / airborne / drift / slide flags, sim tick age), every channel as a bipolar
meter with 1.5 s peak hold, the total force, a 12 s strip chart with event ticks, the event log, the LFE bus with Hz, the game's
music / SFX / voice / channels option bytes (0x654b90..93).

### The LFE rule, in the UI and the code

The shakers are driven by game events and state (engine, road, impacts, hits, landings, weapons, explosions - the mixer's
`Bus.Lfe`), never by the game's audio and never by boosting voice or music. The page says so in a banner; `ffb-panel.py` refuses
(403) any key naming music, voice, the mix or a loopback; `ffb-lfe-live.ps1` opens one output device and no input (header). The
music / voice levels are shown read-only so the owner can see they are untouched. (The `+0x60` "saved copy" of those bytes read
0 0 0 0 live and was dropped.)

## 2. Windowed: what was measured (rc twin `rc-twin-panel-20261025`, OWNER-2300-ALL, t05)

| conf | window (GetWindowRect) | resize from outside |
|---|---|---|
| the RC's `dgVoodoo.wide.conf` (FullScreenMode false, [Glide] 6880x2880, [DirectX] 1680x1050, AppControlledScreenMode true) | 3440x1440, WS_POPUP | - |
| same, [Glide] 2560x1080 | 3440x1440 | - |
| same, [Glide] 5120x2160 + SetWindowPos 4x/s | 3440x1440 | **vetoed**: SetWindowPos TRUE, rect unchanged at once (n 2 boots) |
| + `AppControlledScreenMode = false` | 1680x1050 centred ([DirectX] Resolution) | **holds**: 2560x1070 at 0,0 through the mission load (n 3 boots) |

So `-Windowed` writes, for that launch only (the previous conf is put back when the game exits, verified md5 dccd379a after
every run): `[Glide] Resolution = 2 x the window` (5120x2140, capped 8192 per side) and `AppControlledScreenMode = false`; a hidden
keeper restores the window size 4x a second for the life of the game (top left until sized once, then a move by the player is
kept); `I76_ASPECT` / `I76_U32X_MENU_ASPECT` = the window (proxy log: `aspect: D 2.393, 20/20 sites`, HUD squeeze from the same
k); `I76_NO_MINIMIZE=1` (proxy log: `no-minimize: ... push 6 -> push 8; read back ok`), because the exe minimises itself when it
loses the focus - with the browser opened beside it the game window went WS_MINIMIZE (n 1) before this. The menu pointer map
follows the live client rect by itself (`cursor-map: on (stretched ... over the game window's client rect)`).

Screenshots (lab `captures\ffb-panel-20261025`): **`v4.game-active.png`** (the game 2560x1070 at the left, driving, the panel live
at the right: 54 mph, gear 3, events on the strip), `v4.panel-active.png`, `w4.screen.png`. The firewall prompt in them is another
lane's `nitro.exe`, not this test.

**Known limit, owner's call:** while the panel window has the focus the game is inactive, as it always has been: the sim pauses
(the page shows `PAUSED`) and the game window goes **black** until you click back into it (`v4.panel-active.png`, n 1). The
proxy's `I76_KEEP_ACTIVE` (a lab harness switch) would keep it ticking and drawing, but then the car also keeps going while you
click on the page. Not switched on; say if it should be.

Not verified: the menu pointer in the 2560x1070 window by clicking (the shell path was not clicked through; the map is the same
code the full-screen window uses); a bordered / movable window (the window is borderless at the top left).
