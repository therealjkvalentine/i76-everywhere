## A. Head look

### A1. A held glance key overrides head look

`i76-opentrack-headlook.ahk`: every 8 ms tick asks the OS (`GetAsyncKeyState`, the logical state, so injected keys from the pad
and stick layers count too) whether a glance input that the script did not press itself is down: the four arrows (keyboard, pad
right stick, Fighterstick cone hat all arrive as arrows) and the middle mouse button (`pilot_glance_left`). While one is down:

- DIGITAL releases its own glance keys and presses nothing;
- ANALOG releases its pitch key and **restores the seven input-poll instructions it NOPs**, which is what made key glance inert in
  analog before (its own comment: "keyboard/joystick glance is inert while analog is on"); the engine glances on the key.

On release: ANALOG re-patches and blends its yaw target from the camera's current yaw to the head's over 150 ms (smoothstep);
DIGITAL waits 150 ms before pressing again. The handgun fires on `weapon_fire` while you glance out of a side window
(docs/I76-GAMEPLAY-REFERENCE.md), so the key glance + Enter / trigger is the shot the owner asked for.

### A2. opentrack auto-start: why it never worked, and the fix

Root cause, reproduced 2026-10-24 08:37 (n 1): opentrack 2026.1.0 is a Qt 6 application and its widgets have no window handles,
so the AHK's `ControlGet, Hwnd,, Start, opentrack` found nothing; it timed out after 20.3 s and tracking stayed off
(`FT_SharedMem` absent). UI Automation does see the button: `Start`, AutomationId
`QApplication.main_window.content.groupControls.groupStartStop.btnStartTracker`.

Fix (two independent mechanisms; either is enough):

1. **opentrack's own game detection** (source: opentrack `gui/process_detector.cpp`, `main-window.cpp`): a 1 s timer starts the
   mapped profile when a listed exe runs and stops only tracking it started itself when that exe exits. `PLAY-i76.ps1 -HeadTrack`
   now sets `HKCU\Software\opentrack-2.3\OrganizationDefaults` `executable-detector-enabled=true` and adds `i76.exe` / `I76.EXE` /
   `I76.exe` -> `default.ini` to `executable-list` (exe 0x1F profile, rows 0x1E; existing rows kept) **before** it starts opentrack.
   The values before the change were `executable-list` empty, `executable-detector-enabled=false` (backup:
   lab `builds\controls-20261024\opentrack-reg-before.reg`). It is now a setting of the owner's opentrack: it also starts
   tracking when opentrack is open by hand and any `i76.exe` runs (lab runs included). Off: opentrack Options > Game detection.
2. **`_ahk\i76-opentrack-autostart.ps1`** (hidden, started by the launcher): if tracking is not live (with `-WaitGame`: 6 s after
   the game process appears), it invokes the Start button through UI Automation, retrying until live or 60 s. The old .ahk is a
   wrapper for it.

Both judge success by `FT_SharedMem`'s DataID advancing (`tools\ft-heartbeat.ps1`), never by the mapping existing: a reader such
as the head-look layer keeps the mapping alive after opentrack stops. The launcher no longer waits 20 s for the mapping when game
detection is on (tracking only begins once the game runs).

### A3. Modes

ANALOG by default; Ctrl+Alt+H cycles ANALOG -> DIGITAL -> OFF -> ANALOG. Each change, and the start mode the first time the game
has focus, shows a toast at the top centre of the game window (a click-through, no-activate window: the cursor overlay's recipe)
and beeps (880 / 660 / 330 Hz; `I76_HEADLOOK_BEEP=0` silences). `PLAY-i76.ps1 -HeadLookMode ANALOG|DIGITAL|OFF` (env
`I76_HEADLOOK_MODE`) sets the start mode; the launcher console names the shortcut (the RC's .bat runs it hidden, so the toast is
what the owner sees).

### Found on the way (fixed)

- **The RC map's Up / Down swap (1c397955) broke head-look pitch and the stick's cone hat**: both hard-coded `Down` for
  `pilot_glance_down`, which on 1c397955 is `pilot_glance_up` (look back). Both now read the `pilot_glance_*` blocks (without
  Shift) from the folder's `input.map` at start; repo map -> Down, RC map -> Up (selftest below).
- **The analog patch restore wrote blind**: `SetInputPatch(false)` wrote the Gold bytes back over all seven sites whether or not they
  had matched. It now restores only the sites it patched, and an exe whose seven sites do not all verify gets no analog writes at
  all (it acts DIGITAL and the toast says so). Patch state is also reset when the game process changes (a relaunch used to leave
  `gInPatched` set, so the new process was never patched).

## B. Linked weapons

- **Link key: `F`, unchanged.** Stock I'76 binds `weapon_link` to `L` (`KEYBOARD.MAP`); this project's map moved it to `F` on
  2026-07-04 (the MW5 layout), and `L` became hardpoint 3 on 2026-10-17. `F` is free of every AHK layer's sends except the
  launcher's key-up list. Some docs said "F fires the linked group" (CONTROLS.md s.1 notes, README-TESTER): corrected - F links /
  unlinks; `weapon_fire` (Enter, left mouse, pad RT, stick trigger) fires the selected group, which is the linked group once linked.
  input.map is unchanged (lint OK, map md5 a66a37f7 in the repo; 1c397955 in the RC).
- **Fighterstick trigger** = `weapon_fire` + `hardpoint1_fire`, both held while the trigger is (`Enter` + `1`): the selected /
  linked group, hardpoint 1, and the handgun when glancing out of a side window. There is no separate handgun action
  (CAR-CONFIG.md: the .45 "only fires when you are looking out of the window, using the generic weapon-fire input").
  The script's "one weapon effect per control" rule came from the 2026-08-01 I7_SFRCE.DLL crash, which the docs attribute to force
  feedback failing to start (the Thrustmaster panel holding the device); not re-measured here.
- **Pad**: RT already fires `weapon_fire` (the linked group). New: **LB + Select = link weapons** (`f`); Select alone is still Esc.

Controls sheet (`tools\controls-sheet\build.ps1`): multi-key stick entries supported; status lines for the link key, head look, the
trigger and LB+Select; sources agree, lint OK, `tests/test_controls.py` 5 passed; PDF rebuilt.
