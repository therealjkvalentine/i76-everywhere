# The I'76 Mac Kit: end users build the Mac apps themselves (2026-10-25)

Owner: *"What about end users building the Mac version?"* Until today, every Mac app was built by hand on our Macs: the
Sikarugir wrapper was cloned and grown since July, and the Nitro app was cloned from it (`tools/nitro-mac/make-nitro-app.sh`).
This lane delivers a Mac path that users can build themselves and that redistributes nothing of GOG's: `tools/mac-kit/` and the
zip `Interstate76-Mac-Kit-i76-everywhere-v0.7.4-9cb3a44.zip`, attached to the **draft** release v0.7.4 (not published).

Evidence is in lab `captures\mac-kit-20261025\`:
- `survey\`: the shipped apps' manifests and the pristine GOG manifests
- `compare\`: the comparison of the kit-built apps with the shipped apps
- `final-runs\`: every proxy log and build log

Builds are in lab `builds\mac-kit-20261025\` (`patches\` and `mac-payload\`). The zip is in lab `downloads\mac-kit\`.
Test Mac: the owner's MacBook Pro (Apple M5 Pro, macOS 26.6.2; main display a 3440x1440 monitor). Nobody was at it (idle
more than 2.5 h), and every game was muted (`I76_MUTE=1` plus Wine's null audio driver). All times are CDT.

## 1. The journey (what a Mac user does)

1. **Get the Windows game files.** GOG sells Interstate '76 for Windows only, and the GOG Galaxy app for Mac does not install it.
   On gog.com, under *Account* > *Games* > *Interstate '76*, choose system **Windows** and download the offline installers
   `setup_interstate76_2.1.0.17.exe` (395 MB) and `setup_interstate76_nitro_pack_2.1.0.17.exe` (238 MB). Another way is to copy
   the installed folders from a Windows PC. Both installers are **Inno Setup 5.5.0 (unicode)** files and contain no `.bin`. The
   lab extracted them with innoextract 1.9 in September (`<re-archive>\sandbox-gog\README.md`).
2. **Download and unzip the kit.** The download is 2.0 MB. Unzip it with a double-click.
3. **Double-click `BUILD-I76-APPS.command`.** The first time, right-click > *Open*, because the kit is not from the App Store. It
   asks, in two dialogs, for the installer or the folder. It then runs `i76-mac-kit.sh build`, which needs no sudo, no Xcode and
   no Homebrew. The Terminal equivalent is `./i76-mac-kit.sh build --gold <exe|folder|zip> --nitro <exe|folder|zip>`.
4. **Open the apps** from `~/Applications/Sikarugir/`, where the family Macs keep them too. At the first start, macOS asks
   about the microphone. The first time the user hosts or joins a network game, it asks about Local Network, and it asks about the
   firewall only if the firewall is on. The user-facing README is `tools/mac-kit/README.md`, which the zip ships as `README.md`.

What a GOG installer turns into: if `innoextract` is on PATH, the kit uses it. Otherwise it runs GOG's own installer
(`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /NOICONS /DIR=C:\gogout`) inside a throw-away prefix of the kit's own Wine. That
prefix has Wine's **null graphics driver** (`HKCU\Software\Wine\Drivers "Graphics"="null"`), so no window opens. Measured: the
result is innoextract's `app\` folder, file for file, for both installers. The installer adds a `.lnk` (removed) and leaves out
the empty `music\tracklen.nfo`. Both GOG runs together took 2 min 19 s (with the downloads already cached). A folder is checked
by `i76.exe` / `nitro.exe` md5 before anything is changed. The kit refuses GOG's older 2019 build (60abf7bc), whose patches it
does not carry, and refuses a folder that already holds the Windows Patch Kit.

## 2. The runtime decision

| option | licence / redistribution | Apple silicon | used by our stub today | verdict |
|---|---|---|---|---|
| **Sikarugir** (Gcenx; Wineskin's successor) | Wine is LGPL 2.1, and the wrapper sources are LGPL (Sikarugir-foss-sources). The wrapper repo carries no licence file, and the template bundles Apple's D3DMetal under Apple's restrictive licence. So we **do not rehost it**: the kit downloads the template and engine from Sikarugir-App's GitHub releases, pinned by SHA-256, and deletes D3DMetal along with the other renderers I'76 never uses | yes (x86_64 Wine under Rosetta 2, wow64); macOS 14.6+ | **yes**: every family app is Template 1.0.11 + engine `WS12WineSikarugir10.0_6` | **chosen** |
| Kegworks / Wineskin | LGPL; unmaintained (Sikarugir is its continuation) | partly | no | no |
| Whisky | GPL 3; archived in 2025; built on Apple's GPTK Wine | yes | no (different bundle layout) | no |
| CrossOver | commercial, not redistributable, per-user licence | yes | no | no (a paid prerequisite) |
| Apple Game Porting Toolkit | Apple licence: evaluation and porting only, no redistribution | yes | no | no |

Pins are in `tools/mac-kit/pins.txt`. **Measured equal to the family apps:**
- **Template 1.0.11** (sha256 9fa15479...): its download unpacks file for file to the copy Sikarugir Creator cached on the MacBook (737 files, 0 differ).
- **Engine 10.0_6** (sha256 9da7ee0c...): equal to that cache.
- **DxWnd 2.06.14** (SourceForge RAR, sha256 1d439f18...): the stock macOS `tar` (bsdtar) unpacks it, so no `unar` is needed. It equals the Gold app's `C:\dxwnd`, except the owner's `dxwnd.ini` and `mixer.ini`.
- **IPXWrapper 0.7.2** (sha256 a32255f5...): its three DLLs are 06a01d0f / 70e4a652 / c18759b2, the same as on every LAN machine.

The kit removes the same things `slim-wrapper.sh` removed from the Gold app (wine-mono, wine-gecko, MoltenVK, the renderer
folder). wineboot runs with `WINEDLLOVERRIDES=mscoree,mshtml=`, so no install dialog appears.

## 4. Two fixes the hand-built apps never needed (both are the GOG 2.1.0.17 exe under Wine)

The family Gold apps run the AiO-based 2019 exe (6319abf7). A new user gets GOG's current 2.1.0.17 build (9a232dcc), and the
first boots of the kit-built Gold app showed two differences:

1. **"Please insert CD 'Interstate '76 CD 2'"** at boot (dialog read with `i76probe3.exe boxtext`). On Windows, GOG's installer
   writes `HKLM\Software\(WOW6432Node\)Activision\Interstate '76 Gold Edition "Minimum"="0"` (read on the PC: present, with
   `Interstate '76` `EXE`=i76.exe). A copied folder has no such key. The kit writes it, the same key Nitro needed for its terrain.
   The Deck Kit lane hit the same thing in parallel (commit 9142b92).
2. **The frame-0 PIT CPU-speed probe is fatal under Wine**: `0xC0000096` at exe+0x99997 opened winedbg's "Program Error". On
   Windows the game gets past it (it is the "handled probe" line), and the AiO exe never calls it: AiO replaced the call at
   0x499b25 with GlobalMemoryStatus + `jmp`, as a disassembly of both builds shows. The kit's i76.exe patch also turns
   `call 0x499950` at 0x499b25 into `or eax,-1; nop; nop`, the probe's own failure value, so the caller stores 200 MHz, as Nitro's
   `I76_NITRO_PIT_SKIP` does. Gold's proxy recognises the exe by its PE stamp and checks every site's own bytes, and none is at
   0x499b25. On the Mac it logs neither a CRASH line nor a pit-probe line. This changes i76.exe for the Mac only: the Windows Patch
   Kit's i76.exe stays 64165126. The proxy is unchanged (5d6f9828).
