## 1. What I26 is (read 2026-10-21 from GitHub; the source is not public yet)

- A **reimplementation of Interstate '76 in the Godot engine** that reads the GOG game data (Gold and Nitro Pack; it
  finds GOG installs, also through Wine / CrossOver / Heroic on Linux and macOS, or unpacks the offline installers).
  Author vahokif (Discord "chpatrick"). 17 stars, 117 issues filed in two weeks, no forks, 8 commits on master (the
  source zip holds only the README; issue #80 "planning to release it soon", 2026-10-17; no licence stated).
- Releases: 0.1.0 (7 Oct) .. 0.7.0 (19 Oct 2026). Network protocol 14 at 0.7.0 (every player must match).
- **Two looks:** a modern renderer (lit headlights with shadows, 3D trees, smoke layer, round wheels, caltrops as
  models, Far draw distance to 20 km) and a **1997 mode** (3D-card and a software renderer, palette grade), toggled with
  F12 at any time. Draw distance "Original" clips at 600 m (the stock value we also measured), "Far" is the default.
- **Simulation Rate** is a Play Options setting, default **20 Hz**, with "Modern Physics" following it; 0.7.0 shows a
  one-time warning that other rates "can break the AI, helicopters and physics" because they "were made for 20 Hz".
  Max FPS caps drawing only; cars are drawn interpolated between steps (the same shape as our whole-sim tick).
- **Multiplayer:** its own netcode, dedicated server `i26-server`, internet play through community servers with UDP
  hole punching (no port forwarding), passwords, up to 32 drivers on the host form and 64 on the server, host
  migration (0.5.0: lowest seat takes over, everyone keeps seat / car / score; 0.7.0: the leaving host hands over a
  saved state), Tab standings, kill feed, chat. **Bots (0.7.0):** the host fills free seats with bots (Easy / Normal /
  Hard; `--bots-ai N`, `--bot-skill`), they score, die, **respawn after five seconds**, use regen pads, count toward
  the win, **give up seats as players join and return when players leave, continue under a new host**, play race
  laps and CTF roles, carry instant-melee driver names and a "(bot)" tag on the scoreboard. Respawn for humans: Space
  after 5 s (not automatic); Enter while dead reconfigures the car.
- **Map editor** (0.6.0/0.7.0): terrain brushes, roads in the original RSEG format with intersections, object
  palette, mode markers, a STYLE window; **saves in the original formats, stock maps round-trip byte for byte**, so
  the original game can play the maps.
- Gamepad + force feedback, auto-reverse, mission checkpoints, hidden weapons and cars, crash blur, upscaled-texture
  support, missions load in half the time, native Windows / Linux / macOS (universal app).
- Nitro Pack: campaign, arenas, CTF, race, specials, weapon restrictions, custom Nitro maps, GAME OPTIONS popup.

## 3. What to learn or take

1. **The helicopter is a tick-rate canary.** I26's helicopters crash into terrain at 60 Hz and weave at rates other
   than 20 Hz (#57, 0.6.0 fix "fly straight above 28 Hz"). Our whole-sim tick runs the original helicopter code at
   24 ticks/s; nothing in the gate drives a helicopter mission. **Add a gate row:** a helicopter mission (T08 / the
   police chopper scenes) at 41.667 vs the P166 reference, altitude over terrain and straight flight.
2. **Their issue tracker is a free, player-validated bug list for the original game too.** Items that are engine
   behaviour, not I26's: helicopters altitude in "Break In" (also in the original, per the reporter), AI out of
   ammo in scenarios (#66), AI off Seminole's bridge, respawn tents not detecting cars, mortar range, car explodes
   on jump landing (#7, closed). Each is a candidate "was it like that in 1997?" check for us.
3. **UX choices worth copying as is:** Tab = standings (we have no in-game standings view), "(bot)" tag and
   instant-melee names on AI rows (ours read "Unknown" on joiners), Space to respawn after 5 s instead of automatic,
   Enter while dead to reconfigure, a one-time warning when the sim rate is changed away from the reference, shared
   sim rate set by the host (we pin it in PLAY-LAN; their open request #90 asks for exactly that).
4. **Release discipline:** protocol number in every release note and "everyone needs this version"; a dated changelog
   per release; a test build handed to the reporter within 20 minutes (the 0.6.1 driver fix). Our packs should carry
   a protocol / pack id the host form shows.
5. **Internet play without port forwarding** is what made their multiplayer usable to strangers. Our family plays
   over Tailscale and IPX; bz911 is the only public lobby. Not a priority while the family is the audience, but
   it is the gap a community would notice first.
6. **Modern renderer problems repeat ours:** Far-distance mountain ring drawn over everything, holes in far ground,
   seams on steep slopes, textures missing. Our rc-draw lane fought the same class (barn missing at 1200 m, hill
   edges moving). Worth a read of their fixes once the source is out.

## 4. What we could offer them (community contribution, not competition)

- The **tick measurement**: 1997 hardware stepped 36-47 ms, the reference is 41.667 ms (24 Hz) with the per-frame
  counters at factor 1, not 20 Hz and not 15 Hz; the T05 jump numbers; the four per-frame counters and what breaks
  when they are not corrected (their "AI, helicopters and physics made for 20 Hz" is the same effect).
- Difficulty semantics (50 / 25 / 18 per hit, offline only), the scenario off-by-one, the stock 600 m far clip and
  the 1800 m ceiling, the flamer-damage-in-renderer finding, weapon tables (WEAPON-STATS.md), the ANet 2 packet map
  (NITRO-MP-DESIGN), the bz911 lobby's per-species session lists.
- The i76-map parsers (byte-exact) for their editor's round-trip claim.

## 7. Draft post for the Discord (owner sends; not posted)

> Been working on a different approach to the same problems: a Strlkup.dll proxy that patches the original Gold and
> Nitro exes in memory (the game stays byte-identical, saves and stock multiplayer keep working). Two measurements
> that might help I26's simulation-rate question: we ran the 1997 game on an emulated P166 (86Box) and the car step

> damage offline (50 / 25 / 18 per hit); it never touched the AI. Records and tools: github.com/therealjkvalentine/i76-everywhere.
> Happy to share the ANet 2 packet map if the lobby work is of interest.

## 8. Connecting the Discord to Claude (summary; full setup in technology-services/integrations/discord/AGENTS.md)

Three routes, in order of effort:

1. **Claude in Chrome** (read any server you can see, draft posts, post only with your per-message OK): install the
   extension from claude.ai/chrome, sign in with the same account as Claude Code, restart Chrome. Tried 2026-10-21:
   "Browser extension is not connected", so the extension is not installed on this PC yet. No bot, no token, no
   server admin needed. Reading is a page read of your own logged-in session; nothing is stored.
2. **A Discord bot + an MCP server** (persistent pulls, history, scripted digests): needs a bot you create in the
   Discord Developer Portal with the Message Content intent, invited to the server with View Channels / Read Message
   History. **Only a server admin can invite it**, so this works for servers you run; for the I'76 community server
   you would ask its admins. Community MCP servers exist (v-3/discordmcp, Node; erinlkolp/discord-mcp-server,
   Python / Docker); none is from Anthropic or Discord. Config goes in technology-services `.mcp.json` as a stdio
   server with the token in an environment variable, never in the repo.
3. **Not recommended:** user-token "self-bot" servers and DiscordChatExporter with a user token read everything you
   can see but violate Discord's terms and can get the account banned.
