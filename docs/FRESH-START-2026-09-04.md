# Interstate '76 reverse engineering: the fresh start (2026-09-04)

**What this is.** A from-scratch survey of how Interstate '76 was built, what the world already knows about taking it apart, which techniques work on a binary like this, and a methodology chosen by a judge panel and hardened by two adversarial critics. It was produced under a deliberate rule: **no prior notes from this repo or `../i76-uncap-lab` were read**. Every fact below came from the game files themselves (the pristine GOG 2017 build) or from the public web today, and the load-bearing claims were then attacked by independent skeptic agents (the 18 most important of 87 distinct claims, two skeptics each, 37 verdicts: 16 claims confirmed or narrowed, 1 contested, 1 refuted; the other 69 claims are recorded unverified in the archive). Fold the older work back in later, one claim at a time, through the same gates (section 8).

**How it was produced.** 11 recon agents (4 on the binaries, 7 blind web sweeps), 36 skeptics (two lenses per claim: primary sources vs the bytes), 5 methodology proposals from different angles, 3 judges with different lenses, 1 synthesis, 2 adversarial critics, 1 revision. About 7.7 M subagent tokens, 1,560 tool calls. Everything they wrote is archived, with scripts and raw outputs, at `C:\Users\james\i76-map\recon-2026-09-04\` (685 MB). The full methodology is [FRESH-START-METHOD.md](FRESH-START-METHOD.md).

**Reference binary.** `C:\Users\james\i76-uncap-lab\game\i76.exe.2017galaxy`, md5 `9a232dcc2c164648cff20c414c1f9698`. The live `i76.exe` in both installs is a locally patched copy (md5 `4fabc303...`, imports `u32x.dll`/`WINMM.dll`, +132 bytes of `.text`) and is never ground truth.

## 1. Bottom line

- **It is a Visual C++ 5.0 C program.** Compiled with cl 11.00 (`_MSC_VER 1100`, proven by the embedded LZO banner), linked 1998-02-19 by the Visual Studio 97 SP3 linker (5.10; Rich header records build 7303 / cvtres 5.00.1668), against the **dynamic** `MSVCRT.dll`. So ~97% of the 766 KB of code is game code, not runtime. C-dominant with one contiguous C++ region (0x472df0-0x48d140, ~105 KB: unwind-only exception frames, `operator new` in 6 functions, no vtables, no RTTI). x87 float everywhere (about one instruction in six; 717 functions hold 64% of the code bytes), no SSE/MMX.
- **It is the MechWarrior 2 engine, Win95/Mercenaries line, with the MW2 shell still inside.** The shell DLL contains `MechWarrior 2 Message`, `DATABASE.MW2` (byte-for-byte MW2's database format), `MW2SND.CFG`, 'Mech-lab dialog text and MW2's input vocabulary. Heavy Gear (1997) and Battlezone (1998) are siblings on the same engine; Heavy Gear II and Interstate '82 are not (Dark Side engine).
- **Third-party code is small and known.** Static: LZO 1.00 (exe), 3dfx TexUS (ZGLIDE), Microsoft SideWinder FF SDK helper + VFX effect-file loader (i7_sfrce). Dynamic: RAD Smacker 3.0e (Watcom-built), Activision ANet (LGPL source exists), Glide 2.x, PowerVR SGL, Rendition RRedline (loaded by name from ZREDLINE), DirectX 5 exactly (IDirectDraw2 / Surface3 / IDirect3D2 / Device2, DirectSound3D; DirectInput 5 force feedback only inside i7_sfrce). Absent: Miles, zlib, Borland, Immersion I-FORCE.
- **Architecture is plugin-shaped and address-stable.** Fixed base 0x400000, relocations stripped, no ASLR/NX: every address is a constant forever. Renderer = 19-function C ABI resolved by `GetProcAddress` at 0x426900 into slots 0x608ba4-0x608be4 (18 actually resolved; `GetNumDevice` never is). Shell = `ShellMain`/`ShellWindowProc` with a 27-slot callback table built at 0x4022e0. Force feedback = three pointers 0x52bbdc/e0/e4. Sim clock = `GetTickCount` inside 0x49c920 (called from the main loop at 0x4039b8), dt clamped to [0.001, 0.2] s at 0x4fe428; `timeGetTime` belongs only to the `interval.txt` profiler. Allocation goes through ~26 private Win32 heaps named by subsystem tags (`ordnc`, `clasfn`, `chnkmgr`, `wrldr`...) plus two `VirtualAlloc` pools.
- **The data side is essentially solved.** ZFS (6,116 entries: 493 stored, 1,526 LZO1X, 4,097 LZO1Y) was fully extracted today with a from-scratch decoder; the BWD2 chunk container covers 100% of vehicle/weapon/scenery/mission definitions; terrain is 128x128 u16 tiles; the FSM mission bytecode has a published, debugger-verified opcode model.
- **Nobody has ever had symbols for this family**, and no memory map or Cheat Engine table for the GOG `i76.exe` runtime structures has been published. Physics, AI and the renderer internals are undocumented. That is the work.
- **The chosen method is map-first**: a plain-text, git-versioned symbol/type/evidence map is the product; Ghidra is a cache rebuilt from it in about two minutes; agents draft from exported text, a single merge worker writes, and machine-checked gates (including your own hygiene lessons) decide what enters. Hooks, pokes, proxies and function replacements are generated from the map, never the way it is built. Realistic effort: 12-18 months at 15-20 h/week plus agents to a zero-remainder map of the exe; the shell adds 3-6 months. Section 7 and the full document.

## 3. Engine lineage and where names could come from

Lineage (confidence high unless noted): MechWarrior 2 (DOS 1995, "SIM engine", Eric Peterson) → MW2 for Windows 95 / Mercenaries (1996-97, ANet gen-1, DATABASE.MW2) → **Interstate '76** (Mar 1997; shell built VC 4.2 Jul 1997; Gold rebuild VC5 Feb 1998 with the Z*.DLL plugin layer, shared with MW2 Titanium) → Heavy Gear (Nov 1997, "partly derived from Mercenaries code") and Battlezone (1998, last title on the engine; inherits ZFS, .geo/.sdf/.vdf). The developers said it plainly in 1996-99: the MW2 engine "was held together with super glue and bubble gum", they imported it "subsystem by subsystem" and rewrote "virtually all" of it. Lead programmer Dan Stanfill (ex-JPL); programmers Kurt Arnlund (cockpit displays, weapons, later the 3D-card work with an unnamed contractor), Julio Jerez (later Newton Game Dynamics; physics authorship unconfirmed), Dan Kegel (ANet).

Name and type sources that exist:

- **ANet**: LGPL 2.1 source (anet-0.10, kegel.com/anet, github.com/Nielk1/anet); verbatim strings match the shipped 1997 DLLs; 37 of 42 exports declared in the 0.10 headers. The Call to Power 2 source tree carries `anet2.map` (824 symbols) plus debug builds. Also names `strlkup` (`demo/utils/strlkup.c`) and part of `Getinfo.dll` (`src/aeh/detect.c`).
- **LZO 1.00** source: names the exe's decompressor block (0x4ba980-0x4baed5; LZO1X at 0x4babd8, LZO1Y at 0x4baa00).
- **The 1997 debug shell** (I76SHELL_1083.DLL): asserts with file names; Version Tracking against the 1998 shell (same source, two compilers).
- **Roanish/i76** (2026, MIT): a Ghidra-driven map of *nitro.exe* (~150 functions, ~80 globals, struct layouts). Constants and strings port; addresses do not.
- **That Tony** (2016-17, on Wayback): every data format plus the FSM VM (14 opcodes, verified in a debugger) — but his addresses are from a CD-era build and are mid-instruction in this one.
- **No shipped Win32 build in the family has a symbol table**; MW2/Battlezone engine source is in private custody (Ken Miller). One real lead surfaced by a skeptic: Loki's 2000 Linux port of Heavy Gear II ships **unstripped** ELF libraries (`libshell.so` ~6,500 named functions, `libsim.so`). HG2 is the Dark Side engine, so transfer is limited to shared middleware and conventions, but it is the only large symbol table anywhere near this family.

## 5. The technique catalogue in one page

**Static (`recon\fp-ghidra`, `recon\agent-harness`).** Headless Ghidra rebuilds the whole project in 1 min 54 s and decompiles all functions in 53 s; the decompiled corpus is ~4 MB of C, so a file-based, grep-able export is the primary agent interface and MCP is optional (most Ghidra MCP servers now require Ghidra 12; GhidrAssistMCP supports 11.4). Create functions at data-referenced code addresses (pass 4). Tables are the best anchor source: six BWD2 chunk-descriptor tables (70 distinct handlers), six 125-entry key-name tables, the 232-entry dispatch table at 0x4f9538, the FSM tables. Version Tracking and BSim ship with 11.4.1; BinExport needs a source build; Diaphora is IDA-only. Build Function ID databases only for the static-CRT DLLs (VC 4.2/5.0 libraries exist only as archive.org uploads; legality is yours).

**Dynamic (`recon\dyn-analysis`).** Ranked by leverage per hour: (1) Frida from 64-bit Python into the 32-bit process: an allocation ledger keyed (heap, size, return address) and a call-rate census over the Ghidra function list, which partitions functions into per-tick / per-frame / event / init; (2) WinDbg Time Travel Debugging, which records 32-bit processes on this x64 host and answers "who wrote this address, when, from which allocation" offline (documented; untested under dgVoodoo); (3) scripted-input snapshot differencing of the 1.7 MB `.data` plus private heaps with repeated-measures statistics; (4) proxy `WIN32.dll` (GOG's own winmm shim name: clocks, joystick) and proxy `ZGLIDE.DLL` (the render seam in game terms); (5) Cheat Engine for dissect, pointer scans across respawn, and poke-and-watch validation; (6) DynamoRIO only if TTD fails; (7) PANDA/Win98 last. Cheat Engine's Ultimap is not worth it on this host (VBS running).

**Agent harness (`recon\agent-harness`).** Plain-text map (`functions.tsv`, `globals.tsv`, `types/i76.h`, `evidence/*.json`), status vocabulary `auto → proposed → supported → verified → anchored` plus `library`/`synthetic`, single-writer merge, evidence gates, a sealed truth set for blind accuracy, and a per-function token ceiling. Published failure modes of agent RE: confident misidentification, silent failure on large functions, bulk renames poisoning the database, prompt injection through strings in the binary, metric gaming.

## 6. What the skeptics corrected (the traps to remember)

1. **That Tony's FSM addresses (0x40EBB0 / 0x40D0D0 / 0x40BF40) are not in this build.** Two fall mid-instruction; one is a two-instruction stub. The functions exist at 0x412ce0 (96-way action dispatcher), 0x414670 (14-opcode switch) and 0x410a10 (match_prototype). Peelar's rsqrt at 0x49C310 is likewise another build; here it is 0x495000 with its LUT at 0x655180.
2. **Cross-build addresses never transfer; constants and strings do.** Roanish's Nitro map lands on the GOG exe by unique constants (6 of 8 tried) and string order, with a non-uniform, sign-changing address shift.
3. **File offsets are not VAs.** An early recon draft quoted the FSM prototype table at 0x4c1a8c and the gamekey table at 0x4f26f0; the real tables are at 0x4c2e8c and 0x4f3af0. Every number in the map must carry an address-class tag and pass a check against the bytes.
4. **"No RTTI" is not evidence of C.** VC5 defaults to `/GR-`; the C++ measurement that holds is EH frames, `operator new` sites and vptr stores.
5. **`WIN32.dll` in the import table is GOG's doing**, an in-place rename of `WINMM.dll` to a 2009 shim that plays MP3 music through audiere. The retail exe imported WINMM.
6. **`timeGetTime` is not the sim clock** (profiler only). The sim clock is `GetTickCount` in 0x49c920, with a dt clamp that makes the sim tolerate stalls up to 0.2 s.
7. **The renderer resolves 18 names, not 19**; `GetNumDevice` is never resolved and slot 0x608bb8 is never written.
8. **Ghidra's default analysis silently misses ~310 functions** reachable only through data pointers (callbacks, static initialisers, the 16-handler table at 0x4c2994).
9. **The ZFS loader accepts stored entries for any file** (`flags & 6 == 0` copies raw bytes), so a repacker needs no LZO compressor; LZO 1.00's compressor output is not reproducible with LZO 2.x anyway.
10. **Three shipped modules are debug builds** (1997 shell, WIPX, viddll), which is free evidence, and one Rich-header quirk (no DOS-stub term) will make modern tools call the 1998 binaries tampered.

## 7. The methodology, in brief

Five proposals were scored by three judges (track record; dead-end and false-positive risk; agent grindability and cost). Leaderboard: map-first 127, leverage-first 118, data-first 118, dynamic-first 116, hook-and-replace-first 111. Map-first won on every lens; the others contributed grafts. Two critics then filed 7 fatal and 22 missing items against the synthesis; revision 2 accepts all 29 (no rebuttal survived). The full document is [FRESH-START-METHOD.md](FRESH-START-METHOD.md). Its spine:

- **Phase 0, weeks 1-2, Foundation.** Archive the evidence, lock build identity on the *live image* (not just the file md5), rebuild Ghidra reproducibly, apply the ~300-400 zero-inference anchors (import thunks, table targets, BWD2 handlers, shell callbacks, LZO, funclets), measure the evidence supply per function, seal a truth set, one 3-hour console sitting for the census, ledger, idle-churn p, paused snapshot and the first sentinel-verified label.
- **Phase 1, weeks 2-8, Anchors, tables, leaves, formats.** Name what the anchors reach without inference; DX5/ANet/Smacker typing at the boundaries; the loader spine; leaves-first agent grind with emulated-execution evidence (Unicorn already ran the game's own LZO decoders byte-identically on all 5,623 entries); sim clock, pools, hash tables, hack-prevention functions; anchors-only pass on the shell.
- **Phase 2, weeks 5-12, Globals, structs, dynamic batches.** Type the 7,277 referenced globals by owner and width; sentinel campaigns per format family; the heap/pool object universe; writer-side oracles (I76EDIT, BUILDER.DOC, Asset Bible); debug screens as read-back; the determinism layer (stepped virtual `GetTickCount`, pinned `srand`/`time`, joystick record/replay) with p = 0 as the pass criterion.
- **Phase 3, weeks 10-30, Subsystem closure**, anchors first, x87 last: sound, input, FSM VM (with a conformance corpus of hand-assembled missions), loaders and caches, renderer seams, world/mission/terrain, AI tactics, damage/weapons, physics, netcode call sites, profiler, shell boundary. Each subsystem opens with a contract paragraph; human bytes/day on x87 code is measured and the calendar re-projected.
- **Phase 4, week 28 onward, Long tail and completeness audit.** Forced execution for never-seen code, static unreachability proofs for the residue, bounded arrays for every BSS pool; then the shell.
- **Phase 5, from week 10 in parallel, the tweak-anything layer**, generated from the map: `GLOBAL(addr,type)` header, `i76poke` (every write reads back), `i76hook.dll` loaded through the existing shell `LoadLibraryA` seam, proxy ZGLIDE/WIN32 DLLs, md5-guarded byte patches, differential function replacement for the hard subset. Milestones: frame limiter as a hook, draw distance, FOV, the 0x16c-byte FFB descriptor at 0x4f2328, FSM action injection.

**Gates** (each an executable check): address-class tags with a negative test set; counting-method tags; anchor grammar; two independent evidence kinds; cited field widths and enum bits; per-function library evidence; unique names; bounded arrays; re-decompile consistency; two-view consensus; captures for behaviour claims; a sealed truth set with a halt rule; auto-revert; a token/time ceiling; static-first before any console request; ported names enter as proposals; parser round-trip; emulated I/O; differential replacement split by function class. Your hygiene lessons are gates H0-H10: check which build is live (on the live image), A/A before A/B with n and spread, verify by writing through four channels, read back every write, read the null with its funnel, suspect round constants against instrument scales, invariant frames and independent instances, precise blocker sentences, raw retention with manifests, crashes as captures, and console-session rules (no RDP).

**Metrics:** bytes and counts per status over 765,525 `.text` bytes and 2,165 functions with a strict byte partition; typed bytes and unowned addresses over the data regions; heap/pool types with full field tables; verified labels per channel; blind truth-set accuracy; revert and disagreement rates; tokens per accepted function; console captures and canary failures. Done means remainder counts are zero, not that it feels done.

## 8. Folding the older work back in

From Phase 2 on, one claim at a time, exactly as any external instance: each becomes an evidence record of kind `ported` with its source and build identity, enters as `proposed`, counts as one instance, and reaches `supported` only with an independent GOG-side anchor (string xref, unique constant, table entry, capture, or a Version Tracking match with a stated score). Contradictions are logged as findings, not resolved by seniority. Old raw captures are re-mined under the retention rule if their build identity can be recovered; otherwise they only generate requests.

## 9. Decisions only you can make

1. Acquire Visual C++ 5.0 SP3 (archive.org uploads only; legality is yours)? With it: byte-diff LZO to pin build flags, calibrate on Homeworld/anet, and reccmp becomes a ratchet. Without it: VS2019 `/arch:IA32 /fp:precise` with measured tolerances, no byte-level ratchet.
2. May `nitro.exe` be extracted from the GOG Nitro Pack installer in Downloads into a second sandbox for a 5-day Version Tracking box?
3. Console cadence: how many ~3 h sittings per fortnight, and may Task Scheduler runbooks be installed on the console machine?
4. Token budget: the weekly cap and the acceptable plateau (the plan halts drafting below 5 accepted rows/day with a full queue).
5. After the exe: shell first (garage, lobby, save, difficulty, the mission 12→13 crash at 0x467470) or the renderer DLLs first?
6. May the two-day symbol-leak hunt contact people (Peelar for the Gold HAL beta and netcode files; Ken Miller for Battlezone)?
7. May the playable install ever run the hook DLL for a demo, or does the sandbox stay the only runnable copy?
