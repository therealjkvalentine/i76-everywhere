## Answers to the playtest questions

- **Why the jumps and the body roll work now:** `I76_FIXED_STEP=24` steps the physics in 41.67 ms slices, the
  measured mean step of stock play at 20 fps (which really steps 46.9 / 31.2 ms off the tick clock), whatever the
  frame rate; the first attempt at 40 steps/s fell short. Interpolation hides the step. Details in the playtest doc.
- **120 fps:** the ceiling was ZGLIDE asking dgVoodoo for a 60 Hz refresh; the proxy substitutes the code. Physics
  and AI do not change (fixed step); 4 of 5 frames are interpolated.

## Open items

- **Mirror cadence patch (P5)**: the first build logged `UNEXPECTED bytes` at 0x4457b4 on the sandbox because the
  sandbox exe (md5 85de44a7, built on GOG's 2019 AiO exe) carries GOG's own 13-byte change there: the refresh gate
  is jumped over, so **on the sandbox the rear mirror already redraws every frame** (60/s at 60 fps). The switch
  now handles both layouts; the re-run after the merge is pending the soak.
- **"Insert CD 2" prompt** (P1-09): instrumented in the proxy (`I76_CD_LOG`, four hooks, built) with a static
  finding that rewrites the story: the prompt fires exactly when `startup_IsMinimum` 0x4b2220 answers 1, and with no
  registry value it answers by `FindFirstFileA("miss8")` **relative to the current directory**, which is why
  launches without the game dir as cwd prompted and launches with it never did. Live (sandbox, `autotest\cd2-test.ps1`): the pristine
  exe launched from `C:\Windows` prompted exactly as predicted (`startup_IsMinimum -> 1`, `MSGBOX "Please insert
  CD"`); `I76_CD_FAKE=1` alone turned it into "unable to find required files ... check your working directory". The
  proxy now sets the current directory to the game folder at load (always on, `I76_CWD_FIX=0` disables); with that
  the data resolves, but `startup_IsMinimum` still answered 1 with `miss8` found and registry `Minimum` 0. Re-read
  and measured with the function's own three registry calls: it opens `HKLM\SOFTWARE\Activision`, then
  `RegCreateKeyExA(..., KEY_ALL_ACCESS)` on the existing `Interstate '76 Gold Edition` key, which a **non-elevated**
  process is denied (err 5; registry virtualisation does not redirect it) and the function returns 1 before it
  ever reads the value or looks for `miss8`. So the 6/21 split was launcher elevation, not cwd. The AiO exes
  (daily driver, sandbox `i76.exe`) carry `xor eax,eax; ret` there: GOG patched exactly this. For the pristine
  exes `I76_CD_FAKE=1` (answer 0 when `<game>\miss8` is a directory) plus the cwd fix is the permanent form
  (opt-in for now; candidate for default-on).

## Correction, 22:30: the rebuilt u32x broke the bookmark route (found by James on option 6)

James ran TEST-FRAMERATE option 6 and the engine never started after the menus. Cause: the rebuilt u32x with the
Esc-menu box mapping (md5 037fcb3a), which I had installed in the sandbox after testing it only on the direct
mission boot, melee, the Esc menu and the save screen. On TRIP -> LOAD BOOKMARK -> garage -> DONE the exe's frame
counter never moves (leg-b B1.9: 4 of 4 failing with that build; 3 of 3 completing with the Aug-16 build and with
`u32x_min.dll`). It is not the 120 switch: melee entries at 120 passed 10 of 10 with either build.

**The sandbox now runs `u32x_min.dll` (md5 a5927cea = the Aug-16 build + the ghosting fix only):** bookmark route
2/2, option 6 through the trip menus 2/2 at 120.0 fps, option 5 1/1 at 60.0, save-screen mouse still fixed (10 s
idle, row click, SAVE twice -> overwrite prompt). **The Esc-menu Exit fix is withdrawn** until the box-mapping
build's DONE-path regression is found; use the keyboard in that menu meanwhile.

Also made opt-in the same evening: the CD-prompt instrument (`I76_CD_LOG=1`). Its `shell_cb_17` wrapper forwards
one argument and logged a -1 return on the same path. It was not the cause (the route still failed with it off),
but an always-on hook on a shell callback with an unverified signature does not belong in the default path.
